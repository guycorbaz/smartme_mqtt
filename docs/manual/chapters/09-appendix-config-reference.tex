\chapter{Configuration reference}
\label{app:configref}

Every environment variable and every \code{config.toml} key: name, whether required,
default, and what happens if it is missing. The reasoning behind each lives in
chapter~\ref{ch:config}; this is the lookup table.

\section{The environment}

Four are honoured --- the credential pair, the state directory and \code{RUST\_LOG} --- plus
two reserved names the bridge does not read. Everything else \prog has is in
\code{config.toml}; see section~\ref{sec:configfile}.

\begin{center}
\begin{tabular}{@{}>{\ttfamily}l l p{6.4cm}@{}}
\toprule
\normalfont\textbf{Variable} & \textbf{Req.} & \textbf{Effect} \\
\midrule
SMARTME\_CLIENT\_ID     & yes & smart-me OAuth client-credentials ID. Missing: \prog refuses to publish and says so on the screen. \\
SMARTME\_CLIENT\_SECRET & yes & smart-me OAuth client-credentials secret. Missing: \prog refuses to publish and says so on the screen. \\
\addlinespace
SMARTME\_STATE\_DIR     & no  & Where \code{config.toml} and \code{bdseq.toml} live. Default \code{/data}. \\
\addlinespace
RUST\_LOG               & no  & \code{tracing} filter, console and file alike. Default \code{info}. Stays in the environment deliberately: raising the level is what one does to diagnose a configuration that will not load, so it must be readable before the configuration is. \\
SMARTME\_UI\_PORT       & no  & \textbf{Only consulted when there is no \code{config.toml}}, and ignored the moment one exists --- \code{ui\_port} in the file always wins. It exists because a first run has nowhere to read a port from and must therefore take the default, and \code{8080} is a deployment contract (the Traefik label names it, and so does the image's own smoke test), so it cannot simply be moved. Set it when something else on the machine already holds \code{8080}. A value below \code{1024}, or one that is not a number, \textbf{refuses the start} rather than falling back --- a silent fallback would put the screen somewhere you did not ask for, and you would look for it where you did. \textbf{The image never sets it.} See ADR~0037. \\
\addlinespace
SMARTME\_BASIC\_USER    & --- & HTTP Basic fallback user. \textbf{Not read by \prog}\textsuperscript{*}. \\
SMARTME\_BASIC\_PASSWORD& --- & HTTP Basic fallback password. \textbf{Not read by \prog}\textsuperscript{*}. \\
\bottomrule
\end{tabular}
\end{center}

\footnotesize\textsuperscript{*}\textbf{The Basic fallback is not reachable from the
environment.} \code{smart-me-client} implements it (ADR~0009), but the binary constructs
OAuth client-credentials unconditionally and never builds Basic credentials, so setting
these two variables has no effect --- and because the OAuth pair is required, omitting it in
their favour makes \prog refuse to publish. Wiring it up, or dropping it from the design, is an
open decision.\normalsize

\begin{warning}
\textbf{Eleven variables were withdrawn on 2026-08-04} and setting them does nothing:
\code{SMARTME\_GROUP\_ID}, \code{SMARTME\_NODE\_ID}, \code{SMARTME\_BROKER\_HOST},
\code{SMARTME\_BROKER\_PORT}, \code{SMARTME\_METER\_ID}, \code{SMARTME\_DEVICE\_ID},
\code{SMARTME\_SERIAL}, \code{SMARTME\_PUBLISH\_PERIOD\_SECS}, \code{SMARTME\_API\_BASE},
\code{SMARTME\_LOG\_DIR}, \code{SMARTME\_LOG\_KEEP}. Each is a key in the table below.
\end{warning}

\section{\code{config.toml}}

\begin{center}
\begin{tabular}{@{}>{\ttfamily}l l p{6.1cm}@{}}
\toprule
\normalfont\textbf{Key} & \textbf{Req.} & \textbf{Effect} \\
\midrule
schema\_version      & yes & Currently \code{4}. Another value is refused: there is no migration, and reading an unknown layout by guesswork would start \prog on settings nobody wrote. \\
\addlinespace
group\_id            & yes & Sparkplug group. \textbf{No default}: a host persists what it discovers, so the wrong namespace leaves a tag folder that outlives the process and must be deleted by hand. \\
node\_id             & yes & Sparkplug edge node. Same reason. \\
\addlinespace
broker\_host         & yes & Host or IP of the MQTT broker. \\
broker\_port         & no  & Default \code{1883}. A value that is not a port number is refused rather than silently replaced. \\
\addlinespace
publish\_period\_secs & no & Seconds between publishes. Default \code{30}, minimum \code{5}, maximum \code{300}. There is deliberately no value meaning ``off'': the periodic publish is what lets a host that restarted notice a node whose BIRTH it never saw and ask for a rebirth. \\
\addlinespace
api\_base            & no  & smart-me endpoint. Default \code{https://api.smart-me.com}. Must be \code{https}; a plaintext base is refused. \\
\addlinespace
log\_dir             & no  & Directory for the log file. Unset: no file at all, console only. Set: \code{smartme\_mqtt.<date>.log}, rotated daily. \\
log\_keep            & no  & Rotated files kept. Default \code{7}. Not a positive number: refused on stderr, keeps 7. \\
\addlinespace
ui\_port             & no  & Port the embedded web UI listens on \emph{inside} the container. Default \code{8080}. The container publishes no host port --- Traefik reaches it over a shared Docker network and is the only thing that can. Changing it takes effect at the next restart --- the listener is started once. It does \emph{not} disturb the Sparkplug session. \code{0} is refused, and so is anything below \code{1024}: the bridge runs unprivileged and could never listen there, and since this screen is the only place the value can be changed, accepting it would remove the only way to undo it. \\
\addlinespace
created\_ms          & no  & Written by the bridge, never by you: when this configuration was first saved, in UTC epoch milliseconds. \textbf{Absent means unknown}, and the state screen says so --- a file written before this field existed never acquires one, because there is no true value to write. The file's modification time is deliberately \emph{not} used: a \code{docker cp}, a restore or a \code{touch} would move it, and the screen would show a plausible date that is nobody's change. \\
\addlinespace
last\_change\_ms      & no  & Written by the bridge: when the settings last actually changed. A Save that changes nothing does not move it, so it never comes to mean ``last time somebody pressed a button''. \\
\addlinespace
mapping\_confirmed   & no  & \textbf{Set this by hand on a first run, or nothing is ever published.} Whether a human has checked the meter→topic mapping. \textbf{Absent means \code{false}}, and nothing is published until it is \code{true} --- no connection, no birth. Editing the mapping withdraws it automatically --- and so does editing \code{group\_id} or \code{node\_id}, which are in every topic; editing anything else does not. Writing the file by hand and setting it counts as confirming it. See section~\ref{sec:confirm}. \\
\bottomrule
\end{tabular}
\end{center}

\subsection*{\code{[[meters]]} --- one table per meter}

\begin{center}
\begin{tabular}{@{}>{\ttfamily}l l p{6.1cm}@{}}
\toprule
\normalfont\textbf{Key} & \textbf{Req.} & \textbf{Effect} \\
\midrule
meter\_id  & yes & The meter's short name --- and, since contract~13, \textbf{the Sparkplug device level of every topic this meter publishes on}. A value that cannot be a topic level is refused. Renaming it orphans the series a host has recorded under the old name, so it needs a restart and buries the old device. \\
device\_id & yes & The smart-me device UUID behind it. \\
serial     & yes & The meter's serial. It is published as the \code{serial} property of the device BIRTH and checked against what smart-me reports; a mismatch refuses the meter rather than warning about it. It stopped being the topic level at contract~13. \\
enabled    & yes & Whether this meter is published. Disabling one publishes a \code{DDEATH}; enabling one publishes a \code{DBIRTH}. \\
priority   & no  & Whether this is one of the meters you actually care about. \textbf{Absent means \code{false}.} It changes nothing about what is published --- it is counted on the state screen, so that during an incident you can see at a glance whether the meters that matter are among the affected ones. The bridge cannot deduce it: smart-me reports an id, a name, a serial and two numbers, and no make or model. Marking a meter does \emph{not} withdraw the mapping confirmation. \\
\bottomrule
\end{tabular}
\end{center}

\begin{note}
\textbf{Every meter you enable is polled and published.} That was not always so: until
2026-08-06 the runtime served one, and enabling more was \emph{refused} at startup rather
than silently truncated --- a bridge that quietly published three of your four meters would
have been indistinguishable, from the outside, from one meter having failed. The refusal is
gone because nothing is dropped any more, not because the concern was dropped.
\end{note}

\begin{note}
Any key not in these tables is refused. That is the opposite of the usual default, and it
is the point: an ignored unknown key means a rename reads as \emph{absent}, takes its
default, and \prog runs on a configuration nobody chose. See
section~\ref{sec:configfile}.
\end{note}

\section{Where the web UI listens}

\prog binds \textbf{all interfaces} on \code{ui\_port} inside the container, and the container
publishes \emph{no host port}: Traefik reaches it over a shared Docker network and is the only
thing that can. There is no authentication on the interface, deliberately --- see
\code{docs/adr/0019-no-auth-on-the-config-ui-secrets-are-write-only.md} --- which is exactly
why the port is not exposed to the host by default.

Resolution order, and it is the same order the container's own healthcheck uses:

\begin{enumerate}
  \item \code{ui\_port} in \code{config.toml}, when there is a file --- your choice, and it
        always wins;
  \item otherwise \code{SMARTME\_UI\_PORT} from the environment, for the first run, which has
        no file to read a port from;
  \item otherwise \code{8080}.
\end{enumerate}

A value below 1024 is refused rather than silently replaced: \prog runs unprivileged and could
never bind it, and since this screen is the only place the value can be changed, accepting it
would remove the only way to undo it.

\section{How a meter becomes a topic}
\label{sec:mappingscheme}

Three settings decide every topic \prog publishes, and none of them is invented at publish
time:

\begin{center}
\begin{tabular}{@{}>{\ttfamily}l l@{}}
\toprule
\normalfont\textbf{Setting} & \textbf{Where it lands} \\
\midrule
group\_id & the Sparkplug group --- second level of every topic \\
node\_id & this bridge, as one edge node --- fourth level \\
meters[].meter\_id & the \emph{device} level, one per meter \\
meters[].serial & the \code{serial} property of the device BIRTH --- not a topic level \\
\bottomrule
\end{tabular}
\end{center}

So a meter reads \code{spBv1.0/\textit{group}/DDATA/\textit{node}/\textit{meter\_id}}, and the
values inside it are named for the quantities they carry (\code{Power}, \code{Energy}).
\textbf{The meter id is the device identity on the wire, and the serial is what vouches for it}
--- which is why renaming a meter costs a restart and buries the old device, while changing a
serial replaces the box behind a name that does not move.

\begin{note}
\textbf{These two swapped roles at contract~13} (2026-08-25). The serial was the device level
until then; it was chosen because the bridge reads it off the device itself, and abandoned
because what a supervisor historises is a measuring point rather than a box --- a replaced meter
would otherwise become a new device and break its own series.
\end{note}

\begin{note}
A \code{meter\_id} that cannot be a topic level is refused at validation, not at publish time: a
topic the grammar forbids would otherwise silence that meter with the configuration screen still
reporting it as saved.
\end{note}
