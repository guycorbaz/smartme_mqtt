## FR9 / NFR7 — the verification owed at close, performed

Delivered by ADR 0029 on 2026-08-09 because a real fault demanded it, and never verified as an
epic deliverable until now. Verified against the code and its tests, not the descriptions:

- **FR9's letter** asks that a serial mismatch be *"marked quality BAD and not published"*. What
  is built is **stronger in the safe direction**: the mismatch is refused `Fatal`, latches
  (`identity-mismatch`, `State::Failed` absorbing), values are nulled on the wire, and the cause
  names the repair. A meter name change cannot re-attribute a topic: topics are keyed by the
  configured serial and names appear in no topic.
- **NFR7** asks for verification *"at startup + periodically"*. What is built verifies on
  **every successful fetch**, which subsumes both — and it is enforced by a type, not a rule:
  `fetch_once` cannot return a `Reading` at all, only an `UnverifiedReading`, so the check
  cannot be lost on any branch. Dropping it does not compile (measured, 2026-08-09).
- Tests: `a_device_that_is_not_the_declared_one_is_refused_fatally`,
  `the_device_that_was_declared_is_accepted_unchanged`, and the cause-table latch assertions.
- **The recorded limit stands** and must keep being said: ADR 0029 binds a reading to the device
  the configuration DECLARES, never to the meter the operator MEANT. A self-consistent row with
  the wrong label passes. FR25's human half is the manual's, not the bridge's.

**Verdict: FR9 met above its letter, NFR7 met above its letter, deviation direction fail-safe,
recorded here as the epic-close verification.**

## The five shapes of test failure this epic catalogued

The epic's central lesson, assembled across five stories, each shape caught by a different
mechanism — which is the point: no single discipline catches them all.

1. **One layer above** (2.1–2.3): the property asserted on the in-process value while the wire
   went unprotected. Reverting the whole of ADR 0031 left the suite green. Caught by
   adversarial review; countered by asserting on what a consumer reads.
2. **Unchecked evidence** (2.5): right layer, but three of four falsification notes had never
   been run. All three held when played — which is exactly why the practice is dangerous.
   Caught by reviewing the evidence, not the code.
3. **A layer nothing could reach** (2.6): the property sat behind an `async fn` and a live
   request, so a green suite said nothing either way. Caught by asking what the suite COULD
   say; countered by pure extraction (`classify_device_status`, `decode_device`).
4. **Fixtures modelling the fault** (2.7): every fixture pinned both timestamps, so the tests
   handed back the byte-identical replay the new oracle exists to refuse — our own tests could
   not tell a working feed from a replay. Caught only when an oracle compared two responses.
5. **A falsification that never ran** (2.7, closing day): the `last`-gate mutation came back
   GREEN — the scenario was already refused by a different oracle, so the gate was unwitnessed —
   and without 2.6's run-before-writing rule the note would have recorded a red that never
   happened. The ordering rule is not bookkeeping; it is the only thing that distinguishes a
   falsification from a prediction.

## What worked, and must be kept

- **The golden as a tripwire, not a description.** Six contract moves, every one forced into
  the open by a guard that demands the version move with the vocabulary.
- **Structural criteria over invented numbers, three times**: story 2.2 AC4 refused a tolerance
  band, ADR 0033 refused physical bounds, 2.7 AC2 refused a skew threshold — and each refusal
  produced a *better* criterion (a fact about the meter instead of a number about a building).
- **Reviewing the repair separately from the work** (2.3's rule): it found the rate-limit log
  lying about the very wait it honoured, within hours of the repair shipping.
- **Making things visible as a fault-finding method**: rendering `SourceError` reasons exposed
  two live defects in two days. Nothing renders wrong like a surface.
- **Deciding at drafting** (2.6, 2.7): every criterion that refused to defer to a future
  artifact closed clean; the one that deferred ([#69]'s first wording) had to be reworded.

## What went wrong beyond the five shapes

- **Every repair instruction reached nobody** until 2.6 AC5: `impl Display` and `impl Error`
  for `SourceError` could be deleted with the library still compiling. Weeks of carefully
  written operator guidance, unrenderable.
- **[#74] stood unnoticed from July**: six of the eight fields the client consumes are declared
  nullable and `Device` requires all eight. Found the day the API description was pinned —
  which argues the pinning should have happened in Epic 1, not Epic 2.
- **FR14 had to be written to be seen as wrong.** Cheap this time (no code), but the
  requirement sat in the PRD for a month asking the bridge to hold an opinion.
- **The closing story's own review (2026-08-15) found its gate half-open the day it shipped**:
  a replay with its `Date` header stripped walked through AC5's exemption, because the gate
  tested absence of refusal where re-baselining FR15's yardstick deserved positive evidence.
  Repaired and falsified the same day; the lesson joins the catalogue: **an exemption is the
  most trusting line in a function, and it must demand a voucher, not a non-objection.** The
  same review confirmed the cause-flap at slow meter cadence ([#79], arbitration with [#75])
  and an overclaimed diagnosis in the docs (reworded — the bridge can assert a timestamp
  disagreement, never which side's pipeline caused it).

## Key takeaways

The epic set out to build oracles and spent half its effort learning how to TEST oracles — and
that half is the durable one. Five distinct ways a green suite lied, each now with a
countermeasure that is mechanical rather than remembered. The oracle layer itself closed the
loop it opened on 2026-08-10: the guard built in 2.1 caught 2.2; the rule kept on construction
in 2.3 found its falsification in 2.7; and the last oracle refused, on its first day, the exact
fault our own fixtures had been modelling for a month.
