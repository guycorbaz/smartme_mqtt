## What worked, and must be kept

**A pure functional core with a mechanical guard.** `arch_purity` forbids the code that decides
truth from importing anything async or transport-shaped. Not a convention — a failing test.
Across fifteen stories the invariant never drifted.

**Adversarial review.** 26 findings on one batch, including a *pair that cancelled each other*:
the will could never be updated, and the reconnect session-advance could never fire. Fixing
either alone would have left the broker holding a certificate for a dead session, and a
consumer pairing death to birth by `bdSeq` would have ignored the death and kept a frozen value
on screen. No superficial review finds that.

**Documentary honesty.** Two acceptance criteria were recorded as **unmet** rather than signed
off, with issues raised. That is what let them be closed properly later instead of being
discovered in production.

## What went wrong — three linked patterns

### 1. Self-consistency is not conformance

The quality-code defect shipped from Story 1.8 and survived 148 green tests, a three-layer
adversarial review, and two chaos tests that specifically assert quality propagation. None
could see it: every one compared our encoder to our decoder, or to our own enum.

Worse, the Tier-3 run that found it **nearly reported a false pass**. Steps 1 and 5 looked like
corroboration and proved nothing — step 1's non-good quality came from the metric being `Null`,
step 5's from MQTT Engine's own STALE-on-NDEATH. Step 4 was the only step isolating the
property under test, and it was only challenged because Guy pushed back instead of accepting
the run.

### 2. Tests that pass for the wrong reason — recurring, four distinct mechanisms

- the heartbeat-ordering test was vacuous: the fake clock never advanced (caught in review)
- `chaos_sigterm_no_lie`'s `bdSeq` assertion was a tautology: a fresh state dir yields the
  sentinel, so both sides were the same constant
- its post-death drain ran after the process exit was confirmed, where nothing could fail
- its discriminator spanned two clocks, so a backward NTP step would have passed off the exact
  regression it guarded

The common cause is not carelessness: **a test written against already-correct code proves
nothing by passing.** Deliberate falsification — breaking the code to watch the test go red —
caught all four. It was not systematic at the start of the epic; it became so during it.

### 3. Specifications that defer a decision to an artifact that does not exist

- **FR20** demanded a broker ACK that the protocol does not define at Sparkplug's mandatory
  QoS 0. Not unimplemented — *unimplementable as written*. Discovered at implementation.
- **AR13 and Story 1.13's AC** stated the shutdown mechanism as *either/or* and explicitly
  deferred the choice to the `SIGTERM-NO-LIE` test — which did not exist until Story 1.13. The
  decision therefore sat unmade for the whole epic, as did architecture open item ⑧. When it
  was finally measured, the answer was neither branch: the implementation did **both**.

### Process incident

A review subagent launched with write access modified `qos_for` in production code
(`retain = true`) to test a hypothesis and left it there. The harness then reported the edit as
"intentional, don't revert" — a notification that cannot distinguish an agent's edit from the
author's. Caught by a control `git diff`, reverted, production code verified byte-identical.

## The finding that reframed the retrospective

Raised by Guy: *"I have the impression we somewhat missed the Sparkplug B spec."* Investigated,
and correct. Three tiers:

1. **NCMD / Rebirth is not implemented**, while the PRD requires it in six places — including as
   part of NFR17's definition of the Tier-3 gate. Operational consequence: when MQTT Engine
   restarts or detects a sequence gap it *requests* a rebirth; our node will not answer, and
   Ignition's view stays as it was until the bridge reconnects on its own.
2. **Primary Host / STATE is a total blind spot.** Zero occurrences of "primary host", "STATE"
   or "host application" anywhere in the PRD, epics, architecture, ADRs or manual — while Guy's
   broker carries live `spBv1.0/STATE/IamHost`, `STATE/ignition`, `STATE/SCADA`. Never
   considered, never explicitly ruled out.
3. **Known, recorded deviations**: `bdSeq` fixed per client lifetime rather than incremented per
   CONNECT (documented with its reasoning), no DDEATH, no aliases, no templates. Defensible for
   a skeleton.

**The root cause is upstream of all three.** NFR17 states the Tier-3 test must verify "values,
units, STALE-on-death, **NCMD/Rebirth**". The contract test as written checks the first three.
Story 1.15's own AC is narrower than the NFR it claims to satisfy, and nobody compared them.

This is pattern 1 one level up: the oracle meant to protect us from self-referential testing was
itself **built from the implementation rather than from the specification**. We verified that a
real host accepts what we send. We never verified that we send what the spec requires. Nobody
has walked Sparkplug B clause by clause against the code; the manual's "Known limitations" list
was assembled from what we happened to know was missing, not from an audit.

What Guy sensed is not that there are holes — it is that **we do not know how many there are**.

## Decisions taken

1. ✅ Epic 2 runs a Tier-3 verification **per new quality code**, at the moment it is
   introduced, rather than one pass at the end. `quality_code_probe` is the tool.
2. ✅ Drafting rule: an acceptance criterion may not defer its decision to an artifact that does
   not yet exist. Either decide at drafting time, or create the measuring spike first.
3. ✅ **An Epic 1.5 (conformance) runs before Epic 2** — option (b). Rationale: Epic 2 stacks
   sophisticated oracles, and Epic 1 just demonstrated what stacking on an unverified channel
   costs. Epic 2 starts once the size of the conformance gap is known.

## Key takeaways

1. **An external oracle earns its cost the first time it runs** — but only if its steps are
   designed so that each can fail *only* for the reason under test. Two of five steps here
   could not.
2. **A test written against correct code proves nothing by passing.** Falsify, or do not claim
   the guarantee.
3. **Build the oracle from the specification, not from the implementation** — otherwise it
   inherits precisely the blind spots it exists to cover.
4. **A specification that defers a decision to a future artifact leaves that decision unmade**,
   and nobody notices until something forces it.
