# Epic 7 retrospective — deployment, and the difference between delivered and proved

*Written 2026-08-20, the day both its stories were closed. The shortest epic in this project:
two stories, and neither of them built very much.*

## Delivered

| Story | What it settled |
| --- | --- |
| 7.1 | The healthcheck the image can actually run — [#56] closed after fifteen days, ADR 0041 |
| 7.2 | Every Epic 7 requirement tied to something that runs, and the two proofs that were missing written |

**Almost nothing was built, and that is the finding rather than an apology.** The `Dockerfile`,
the compose file with its Traefik posture, and the publish workflow were all in the tree before
this epic began — delivered by Epic 0 and by scattered commits, claimed by no story. What Epic
7 owed was one mechanism (the healthcheck) and a great deal of proof.

## Follow-through on Epic 6's action items (F1–F5)

- **F3 — check the FR coverage map at every epic close.** Applied at the **open** instead, and
  it changed the plan: the inventory found FR39, FR40, AR11 and AR22 already delivered, so the
  epic became a verification exercise rather than a build. This is the action that paid.
- **F1 — quote the criterion verbatim, then answer it.** Honoured in both stories' completion
  notes. 7.1's review still found a gap — the probe was never tested against a non-200 answer —
  which says F1 catches *mis-stated* coverage and not *missing* coverage. Both reviews were
  still needed.
- **F5 — a screen nothing links to does not exist.** No screen shipped this epic; the analogous
  defect did appear, in 7.2's own gate check, which produced no output at all on a machine
  without Docker.
- **F2, F4** — no occasion arose.

## What worked, and must be kept

**Answering an old issue the day its precondition exists.** [#56] was opened on 5 August and
said, correctly, that AR12's restart could not fire because nothing inside the image could
consume `/healthz`. It could not be answered until `/healthz` existed with something worth
probing — which Epic 6 finished. The Dockerfile had carried the trigger in a comment since Epic
0: *"the HEALTHCHECK line belongs in the same change as the endpoint it probes"*. **A deferral
that names its own precondition is a deferral that gets honoured.**

**Deciding among the issue's own options, in an ADR, before writing the code.** [#56] named
three ways out; ADR 0041 takes one and records why the other two are worse — including that
probing from outside the container cannot satisfy AR12 at all, which would have made "we chose
that" a synonym for "AR12 is not implemented".

**Proving a claim where it can actually be checked.** FR40's evidence was a struct written and
read back — a claim about `serde`. The gesture it names is a *new container on an old volume*,
and that is now what runs.

## What went wrong

**1. Two tests in this epic could not fail for their own reason, and both were written by the
same hand that wrote the code.**

- 7.1's unknown-argument test used `Command::output()`. Under its own mutation the process
  never exits, so the falsification was a **hang** rather than a red test — and a hang in CI is
  indistinguishable from a slow machine.
- 7.1's healthy-case test ran on the default single-threaded test runtime, where
  `Command::output()` blocks the very runtime serving `/healthz`. It reported a defect in the
  bridge where the defect was in the harness — Epic 4's action E2, arriving again.

**2. The story shipped without testing the one state the feature exists for.** 7.1's probe was
exercised against a healthy endpoint and against no endpoint, and never against a `/healthz`
answering non-200 — which is precisely what AR12 restarts on. Found by review, not by the
completion note, which had quoted the criterion.

**3. This epic introduced a defect into the gate.** 7.2's compose check `export`ed the two
credential variables, leaving them set for every later step including the whole Rust suite —
the exact hazard 6.6's test had already been hardened against. A gate that hands the suite a
credential changes what it is measuring.

## Action items

| # | Action | Category | Why now |
| --- | --- | --- | --- |
| G1 | **A test that waits on a process waits with a deadline** — never a bare `output()`/`wait()` | Process→Mechanism | The falsification of 7.1 AC3 was a hang; in CI that is a timeout somebody blames on the runner |
| G2 | **Falsify a probe against every verdict it can return**, not only the one the happy path takes | Process | 7.1 shipped without exercising the 503 that AR12 exists for |
| G3 | **Never `export` in `ci-local.sh`** — environment set for one command goes on that command | Process→Mechanism | This epic did it, and this repository had already paid for per-process environment leakage once |
| G4 | **A check that cannot run says so** — a skipped step prints; it does not vanish | Process | The compose check produced no output at all where Docker is absent, which reads as a pass |

## Readiness assessment

**Epic 7 is closable.** Both stories are settled, six requirements each have a row and a proof,
and the two rows that are not proved say `unproven` in Epic 4's convention rather than being
dressed up. [#56] closes with it.

**And the bridge is now deployable in the sense the epic promised**: the image reports its own
health, an update is a new container on the same volume and has been seen to be one, and the
reference deployment parses both ways it is offered.

**What is still not proved, and it is the same sentence as three epics running:** the contract
this bridge emits has been attested against a live Ignition **once**, on 2026-08-03, at
`CONTRACT_VERSION` 3. It emits 10. Epic 8 owns that session as its release gate, and nothing
before it can substitute for it.

## Key takeaways

- **Inventory before planning.** The action written to close epics is more useful when it opens
  them: it turned this epic from a build into a verification, correctly.
- **A deferral that names its precondition gets honoured.** The Dockerfile's comment was a
  fifteen-day-old instruction that landed exactly when it said it would.
- **Two of this epic's three defects were in tests, not in code** — and both were the kind that
  still pass while being unable to fail.
